
# تطوير صفحة تسجيل الدفعة — دفعات متعددة الأشهر

الفكرة الأساسية: المستخدم يكتب **مبلغًا واحدًا** ويحصل على تسوية تلقائية واضحة، مع إمكانية التحكم اليدوي عند الحاجة، وكل ذلك مرتبط مباشرة بشارة المتأخرات الموحَّدة.

## 1) واجهة الاختيار — وضعان متبادلان

داخل بطاقة "المتأخرات" الحالية، نضيف Tabs صغيرة:

```text
┌─ هذه الوحدة عليها متأخرات: 750.000 (3 أسطر) ─┐
│  ( ● توزيع تلقائي )   ( ○ اختيار يدوي )       │
└────────────────────────────────────────────────┘
```

**وضع "توزيع تلقائي" (الافتراضي):**
- حقل واحد: "المبلغ المُحصَّل".
- تحت الحقل **معاينة مباشرة** تُحدَّث مع كل ضغطة مفتاح:
  ```
  500.000  →  يناير ✓ كامل  ·  فبراير ✓ كامل  ·  مارس: 100/250 جزئي
  ```
- التوزيع من **الأقدم إلى الأحدث** (يشمل "متأخرات سابقة" أولاً ثم الأشهر).

**وضع "اختيار يدوي":**
- قائمة المتأخرات تظهر مع **Checkboxes** بجانب كل سطر.
- المبلغ يُحسب تلقائيًا = مجموع المختار، ويمكن تعديله يدويًا (مع تنبيه إذا اختلف).
- يُستخدم للحالات الخاصة (تخطّي شهر، دفع مارس قبل فبراير...).

## 2) إذا تجاوز المبلغ إجمالي المتأخرات

- نُنشئ تلقائيًا صف دفع للشهر التالي (دفعة مقدَّمة) بقيمة `min(الفائض, إيجار الشهر)`.
- إن بقي فائض بعد ذلك → صف لشهر يليه، وهكذا.
- شارة واضحة في المعاينة:
  ```
  ⚡ يشمل دفعة مقدّمة: أكتوبر (كامل) + نوفمبر (50/250)
  ```

## 3) ربط الدفعات بالمتأخرات في قاعدة البيانات

- نُنشئ **صف payments منفصل لكل دورة شهرية مغطاة**، كلٌّ بـ `period_start/period_end` الصحيحَين و`expected_amount` و`notes` وصفية.
- جميعها تشترك في نفس `receipt_number` و`payment_date` و`payment_method`.
- هذا يجعل `getUnitArrears` يستهلكها فورًا ويُنقِص الشارة بدقة.
- نُحدِّث `units.opening_balance_date` إلى اليوم التالي لأبعد `period_end` مُغطّى، و`opening_balance = 0` عند تغطية الفترة السابقة.

## 4) إيصال PDF موحَّد بجدول تفصيلي

`buildReceiptHTML` يستقبل جدول `breakdown[]`:

```text
┌────────────────────┬───────────┬──────────┐
│ الفترة             │ المتوقع   │ المُسدَّد │
├────────────────────┼───────────┼──────────┤
│ متأخرات سابقة     │ 100.000   │ 100.000  │
│ يناير 2026         │ 250.000   │ 250.000  │
│ فبراير 2026        │ 250.000   │ 150.000  │
│ (دفعة مقدمة) مارس  │ 250.000   │  50.000  │
├────────────────────┴───────────┼──────────┤
│ الإجمالي                       │ 550.000  │
└────────────────────────────────┴──────────┘
```

## 5) تأكيد الحفظ (Toast)

```
تم الحفظ ✓
المتأخرات: 750.000 ← 250.000
دفعة مقدمة: 50.000 لشهر مارس
```

## 6) تحسينات صغيرة مرافقة

- إخفاء الـ Checkbox القديم "تحصيل المتأخرات السابقة" (أصبح غير ضروري).
- زر سريع تحت حقل المبلغ: **"= كامل المتأخرات"** و**"= إيجار شهر"** و**"= متبقي الشهر الأقدم"**.
- إظهار إيصال PDF بزر "تنزيل" بدل التنزيل التلقائي، مع زر "إرسال واتساب" مستقبلاً.

## التفاصيل التقنية

ملفات متأثرة:
- `src/components/AddPaymentDialog.tsx` — إعادة هيكلة الواجهة، إضافة Tabs + معاينة التوزيع + منطق `distribute(amount, cycles)`.
- `src/lib/balance.ts` — تصدير دالة جديدة `distributePayment(amount, cycles, rentAmount)` تُرجع `{ allocations: [{periodStartIso, periodEndIso, amount, label, isAdvance}], remainder }`.
- `src/lib/balance.test.ts` — اختبارات للتوزيع: مبلغ يغطي جزء/كامل/مع فائض/فائض يولّد دفعة مقدمة.
- `src/lib/pdfDocs.ts` — `buildReceiptHTML` يدعم `breakdown[]` بدل `unpaidMonths` المنفصل.

لا تغييرات على قاعدة البيانات. كل الصفوف تستخدم schema `payments` الحالي.

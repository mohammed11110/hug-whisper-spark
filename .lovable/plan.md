## التشخيص

### حالة قاعدة البيانات الآن (لكلا الوحدتين)

**B1 #11** (إيجار 120، advance):
- `opening_balance = 0`, `opening_balance_date = 2026-06-01`
- يوجد دفعة 13/5/2026 بمبلغ 100 لشهر مايو (المتوقع 120) → **20 ر.ع متأخرات لمايو**.

**B1 #5** (إيجار 85، arrears):
- `opening_balance = 0`, `opening_balance_date = 2026-06-01`
- دفعة 22/5 بمبلغ 85 لشهر أبريل (مسدّد كاملاً ✓).
- دفعة 22/5 بمبلغ 40 لشهر مايو (المتوقع 85) → **45 ر.ع متأخرات لمايو**.

في الحالتين، `opening_balance_date` تمّ تقديمه إلى `2026-06-01` (أول يوم بعد مايو). ولأن `getUnitArrears` لا يفحص إلا الدورات من المرسى فصاعداً، صار شهر مايو «أقدم من المرسى» = مُسوَّى وهمياً → اختفت الـ 20 والـ 45.

### السبب الجذري
هذه بيانات **مفسدة من bug قديم** في `AddPaymentDialog.tsx` (نفس الخلل الذي أُصلح أمس وأُحكم اليوم في `EditUnitDialog.tsx`). كانت الشيفرة قبل الإصلاح تُقدِّم `opening_balance_date` دون قيد عند أي دفعة. الدفعات (13/5 و22/5) سبقت الإصلاح، لذا تركت آثاراً.

الكود الحالي في `AddPaymentDialog.tsx` (سطور 452–488) **سليم**: لا يُقدِّم المرسى إلا عند `isFullySettled = true`. لا حاجة لتعديل منطقي إضافي، فقط استعادة البيانات.

## الخطة

### 1) استعادة البيانات (data migration واحدة)
سحب المرسى للخلف ليبدأ من أول مايو 2026 في كلا الوحدتين، مع إبقاء `opening_balance = 0`. عند ذلك يحسب `getUnitArrears` تلقائياً:
- B1 #11: rent 120 − paid 100 = **20** ✓
- B1 #5: rent 85 − paid 40 = **45** ✓ (دفعة أبريل قبل المرسى فلن تُحتسب مزدوجة)

```sql
UPDATE public.units
   SET opening_balance_date = '2026-05-01',
       opening_balance = 0
 WHERE id IN (
   '3402a79e-fd4d-4742-ac8a-5df65f034d0a', -- B1 #11
   '4a9dd385-aa0b-48e4-87cf-88b39c0a996f'  -- B1 #5
 );
```

### 2) فحص شامل لباقي الوحدات المتأثرة بنفس الـ bug القديم
استعلام للكشف عن كل وحدة فيها دفعة جزئية (`amount < expected_amount`) ومرساها `opening_balance_date` تجاوز `period_end` لتلك الدفعة دون وجود تسوية. للوحدات المكتشفة، تطبيق نفس قاعدة الاستعادة (إرجاع المرسى إلى `period_start` لأقدم دفعة جزئية لم تُسوَّ).

سأعرض القائمة قبل تنفيذ أي UPDATE جماعي، لتأكيد المستخدم.

### 3) لا تغييرات على الكود
- `AddPaymentDialog.tsx` و `EditPaymentDialog.tsx` و `EditUnitDialog.tsx` تمّ إصلاحها سابقاً. لا regression جديدة مكتشفة.
- لن أُضيف اختبارات جديدة (السيناريو مغطّى في `balance.test.ts`).

## السياق الحالي
- بيانات المستأجر مخزّنة **مباشرة على صف `units`** (`tenant_name`, `tenant_phone`, …)
- جدول `payments` مرتبط بـ `unit_id` فقط — **بدون ربط بالمستأجر**
- عند تغيير المستأجر تختلط مدفوعات/مستحقات القديم بالجديد، ولا يوجد سجل تاريخي

## المشكلة عند الإخلاء مع مستحقات
- إذا حذفت المستأجر القديم → تضيع بياناته ومستحقاته
- إذا أبقيته مع مستأجر جديد → يتداخل الاثنان على نفس العين
- لا يمكن إصدار كشف حساب منفصل لكل مستأجر، ولا متابعة دين المستأجر السابق بعد رحيله

---

## الحل المقترح: جدول "العقود/الإيجارات" (Tenancies)

نُحوّل بيانات المستأجر من **حقول على الوحدة** إلى **عقود إيجار متعدّدة لنفس الوحدة عبر الزمن**.

### 1. جدول جديد: `tenancies`
```
id, unit_id, building_id,
tenant_name, tenant_phone, tenant_email,
tenant_id_type, tenant_id_number, tenant_id_image_url,
contract_start_date, contract_end_date, contract_type,
rent_amount, rent_type, due_day,
security_deposit, deposit_status, deposit_refunded_at,
status: 'active' | 'ended' | 'evicted',
ended_at, ended_reason, outstanding_at_end (numeric),
notes, created_at
```
- **شرط:** عقد واحد فقط `active` لكل وحدة في نفس الوقت (constraint جزئي)

### 2. تعديل `payments`
- إضافة عمود `tenancy_id` (nullable في البداية للتوافق)
- كل دفعة جديدة تُربط بعقد محدد → لا اختلاط

### 3. تعديل `units`
- تبقى `tenant_name/phone/...` مؤقتاً (للتوافق) لكن تصبح **مرآة للعقد النشط فقط**
- عند عدم وجود عقد نشط → الوحدة `vacant` تلقائياً

## سير العمل (UX) في صفحة الوحدة

### زر جديد: **"إخلاء المستأجر"** (End Tenancy)
يفتح حواراً يطلب:
1. **تاريخ الإخلاء**
2. **سبب الإخلاء** (اختياري: نهاية عقد، طرد، انسحاب…)
3. **حساب المستحقات تلقائياً**: يعرض رصيد المستأجر = (الإيجار المستحق حتى تاريخ الإخلاء + الرصيد الافتتاحي) − (المدفوع) − (التأمين إن أُعيد)
4. خيارات معالجة الرصيد:
   - ☑ **الدين مُسوَّى** (تم التحصيل / إعفاء)
   - ☑ **ترحيل كدَين معلّق** على المستأجر السابق
5. **مصير التأمين**: مُعاد / مُحتجز جزئياً / مُحتجز كاملاً
6. عند التأكيد:
   - العقد ينتقل لـ `status='ended'` مع `outstanding_at_end`
   - الوحدة تصبح **شاغرة**
   - حقول المستأجر على `units` تُفرَّغ
   - جميع المدفوعات السابقة تبقى مرتبطة بالعقد المنتهي

### زر: **"إضافة مستأجر جديد"** (يظهر فقط للوحدة الشاغرة)
- نفس بيانات الإيجار الحالية + تاريخ بدء العقد
- ينشئ عقداً جديداً `active`
- يحدّث mirror fields على `units`

### تبويب **"السجل"** على صفحة الوحدة
- قائمة بكل العقود السابقة + الحالي
- لكل عقد: المدة، إجمالي المدفوع، رصيد الإغلاق، الحالة
- النقر على عقد قديم → كشف حساب كامل (المدفوعات + المستحقات + ملاحظة الإخلاء)

### صفحة **"المستحقات السابقة"** (اختياري)
- قائمة بكل العقود `ended` ذات `outstanding_at_end > 0`
- لكل واحد: زر "تسجيل تحصيل" (يضاف كدفعة على العقد المنتهي) أو "إعفاء"

---

## التوافق مع البيانات الحالية (Migration)
- لكل وحدة لديها `tenant_name` غير فارغ → ينشأ تلقائياً **عقد `active`** بنفس البيانات
- كل المدفوعات الموجودة لتلك الوحدة → تُربط بهذا العقد عبر `tenancy_id`
- لا يفقد المستخدم أي بيانات

---

## الفوائد
| الموقف | النتيجة |
|---|---|
| إخلاء مع مستحقات + تأجير لمستأجر جديد | كل مستأجر له سجله المنفصل، لا اختلاط |
| إخلاء مع مستحقات + بقاء العين شاغرة | الدين محفوظ، العين قابلة للتأجير الفوري |
| مراجعة تاريخ الوحدة | كل العقود مرئية بترتيب زمني |
| مطالبة قانونية بمستأجر سابق | كشف حساب جاهز من العقد المنتهي |
| التأمين | حالة منفصلة لكل عقد |

## النطاق المقترح للتنفيذ (مرحلتان)

### المرحلة 1 — البنية الأساسية (مطلوب الموافقة لبدء التنفيذ)
1. Migration: جدول `tenancies` + RLS + إضافة `tenancy_id` لـ `payments`
2. Migration بيانات: تحويل العقود الحالية تلقائياً
3. حوار **"إخلاء المستأجر"** + حوار **"مستأجر جديد"**
4. تحديث صفحة الوحدة: إخفاء بيانات المستأجر إذا شاغرة، إظهار الزر المناسب

### المرحلة 2 — السجل والتقارير
5. تبويب "سجل العقود" داخل صفحة الوحدة
6. صفحة "المستحقات السابقة" + إصدار كشف حساب PDF لعقد منتهٍ
7. تحديث تقارير التحصيل الشهري لتفصل بين عقد نشط/منتهٍ

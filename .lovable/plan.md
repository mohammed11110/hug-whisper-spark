# خطة: ترقيم العقود في "أملاكي"

## الهدف
كل عقد إيجار يأخذ **رقماً فريداً مرئياً** يربط المستأجر + المدفوعات + الإيصالات + الإخلاء بهوية واحدة لا تضيع.

---

## 1. هيكل البيانات (جدول `tenancies`)

إضافة عمودَين:

| العمود | النوع | الوصف |
|---|---|---|
| `contract_number` | `text` (فريد) | الرقم الداخلي التلقائي — مثلاً `AML-2026-0042` |
| `official_contract_number` | `text` (اختياري) | رقم الجهة الحكومية/البلدية لو وُجد |

+ تسلسل (`sequence`) عالمي للحساب: `tenancy_contract_seq`.
+ دالة `generate_contract_number()` تُولّد: `AML-{YEAR}-{seq:0000}` تلقائياً قبل الإدراج (trigger BEFORE INSERT).

## 2. ترقيم العقود الموجودة رجعياً

migration تمرّ على كل عقود الحساب مرتبة حسب `created_at` تصاعدياً وتعطيها أرقاماً حسب سنة الإنشاء:
- عقد ياسر صلاح (وكل العقود السابقة) → يحصل على `AML-2026-0001`, `AML-2026-0002`, ...

## 3. واجهة المستخدم

### عند إنشاء عقد جديد (`NewTenancyDialog`)
- لا يُطلب من المستخدم إدخال شيء — الرقم يُولَّد تلقائياً ويُعرض بعد الحفظ في توست:
  > "تم إنشاء العقد رقم **AML-2026-0043**"
- حقل اختياري جديد: **"الرقم الرسمي (بلدية / سند)"** — يُترك فارغاً افتراضياً.

### تعديل عقد قائم
- يظهر الرقم الداخلي **للقراءة فقط** (لا يُعدَّل).
- الرقم الرسمي يبقى قابلاً للتعديل في أي وقت.

### عرض الرقم في:
1. **بطاقة الوحدة** في `UnitDetail` — تحت اسم المستأجر: `عقد رقم: AML-2026-0042` (+ الرقم الرسمي بين قوسين إن وُجد).
2. **قائمة المستأجرين** `Tenants.tsx` — عمود/شارة صغيرة sage.
3. **PDF الإيصالات والعقد** (`pdfDocs.ts`) — في الهيدر بخط بارز.
4. **شاشة الدفع** (`AddPaymentDialog`) — يظهر تحت اسم المستأجر للتأكيد قبل الحفظ.
5. **شاشة الإخلاء** (`EndTenancyDialog`) — يطبع "إنهاء العقد رقم …" في وثيقة الإخلاء.
6. **البحث الشامل** (`GlobalSearch.tsx`) — كتابة `AML-2026-42` أو حتى `42` تفتح العقد مباشرة.
7. **سجل النشاط** — يُذكر رقم العقد بدل "مستأجر س".

## 4. ربط المدفوعات والإخلاء (لا تغيير منطقي)

المدفوعات والإخلاء **مرتبطة فعلاً** بـ `tenancy_id` في قاعدة البيانات. الجديد فقط أن المستخدم يرى **رقماً مفهوماً** بدل UUID داخلي. لا حاجة لتغيير منطق `recompute_unit_state` أو الإيصالات — فقط نضيف عرض الرقم.

---

## ما لن يتغيّر
- لن نلمس حساب الأرصدة أو المتأخرات.
- لن نغيّر طريقة ربط المدفوعات بقاعدة البيانات.
- لن نمنع تكرار `official_contract_number` (لأنه قد يتأخر في الإصدار).

## ما سيتغيّر تقنياً (للمراجعة)

```text
DB migration:
  ├─ CREATE SEQUENCE public.tenancy_contract_seq
  ├─ ALTER TABLE tenancies ADD contract_number text UNIQUE
  ├─ ALTER TABLE tenancies ADD official_contract_number text
  ├─ CREATE FUNCTION generate_contract_number() → trigger BEFORE INSERT
  └─ Backfill: UPDATE tenancies SET contract_number = 'AML-' || EXTRACT(YEAR FROM created_at) || '-' || LPAD(row_number, 4, '0')

Code:
  ├─ NewTenancyDialog.tsx — toast يعرض الرقم بعد الحفظ + حقل "الرقم الرسمي"
  ├─ EditUnitDialog.tsx / Edit tenancy — عرض رقم + تعديل الرقم الرسمي
  ├─ UnitDetail.tsx, Tenants.tsx — عرض الرقم
  ├─ AddPaymentDialog.tsx, EndTenancyDialog.tsx — عرض الرقم في الترويسة
  ├─ pdfDocs.ts — طباعة الرقم في كل الوثائق
  └─ GlobalSearch.tsx — دعم البحث بالرقم
```

## الفوائد العملية
- في حالة "ياسر صلاح": أي إيصال أو دفعة بعد الآن تُختم بـ `AML-2026-0001` → يستحيل أن يُفسَّر دفعه خطأً كرصيد آخر.
- عند نزاع مع المستأجر: مرجع رسمي واحد.
- جاهز للتكامل مستقبلاً مع الأنظمة الحكومية (سند، بلدية مسقط) عبر الحقل الاختياري.

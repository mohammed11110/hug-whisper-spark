# خطة المراجعة الشاملة لتطبيق أملاكي

سأقوم بفحص التطبيق بالكامل وتجربة مميزاته، ثم تسليمك **تقريراً مبسطاً** بالعيوب وطرق حلها — بدون أي تعديل على الكود في هذه المرحلة.

## ١. نطاق المراجعة

سأغطي كل أقسام التطبيق الرئيسية:

- **الحساب والدخول**: التسجيل، تسجيل الدخول، نسيان كلمة المرور، تأكيد البريد.
- **الاشتراكات والباقات**: الباقة المجانية، التجريبية، المدفوعة، أكواد الترويج، الترقية/الإلغاء.
- **المباني والوحدات**: إضافة، تعديل، حذف، حدود الباقة.
- **المستأجرين والعقود**: إنشاء عقد، إنهاء، تجديد، الودائع.
- **المدفوعات**: إضافة، تعديل، حذف، الإيصالات، المتأخرات، سلة المحذوفات.
- **الصيانة والمصروفات**: الطلبات، الصور، الفواتير.
- **الإيجار اليومي**: الحجوزات، التقويم، التسعير، التنظيف، الرسائل.
- **التقارير والنسخ الاحتياطي**: التصدير CSV/PDF.
- **الإشعارات**: داخل التطبيق، البريد، WhatsApp، Push.
- **الفريق والصلاحيات**: الدعوات، الأدوار.
- **المساعد الذكي (AI)**.
- **الإعدادات واللغة والثيم**.
- **PWA / التثبيت / العمل بدون إنترنت**.

## ٢. منهجية الفحص

سأستخدم ثلاث طبقات للفحص:

1. **فحص الكود الثابت** — قراءة الصفحات، الـ hooks، الـ RLS، الـ edge functions، الـ migrations الأخيرة، والبحث عن:
   - أخطاء منطقية (مثل مشكلة promo code التي ظهرت سابقاً).
   - ثغرات أمنية في RLS و GRANTs.
   - استعلامات غير محسّنة (limit 1000، N+1).
   - تسريبات مفاتيح أو منطق client-side حساس.
2. **فحص ديناميكي بالمتصفح** — تشغيل التطبيق وتجربة المسارات الرئيسية، مع رصد:
   - أخطاء console و network.
   - مشاكل واجهة (RTL، responsive على 713×583، dark mode).
   - حالات فارغة (empty states) ورسائل خطأ.
3. **فحص قاعدة البيانات** — استعلامات قراءة على الجداول الحساسة (subscriptions, promo_codes, profiles) للتأكد من اتساق البيانات.

## ٣. شكل التقرير النهائي

سيكون التقرير **مبسطاً وبالعربية**، مقسّماً حسب الأولوية:

```text
🔴 حرج     — يكسر وظيفة أساسية أو ثغرة أمنية
🟠 مهم     — يربك المستخدم لكن يوجد بديل
🟡 تحسين   — تجربة استخدام أو أداء
🟢 تجميلي  — تصميم/ترجمة/تفاصيل بصرية
```

لكل عيب:
- **ما المشكلة؟** (جملة واحدة بلغة بسيطة)
- **أين تظهر؟** (الصفحة/الميزة)
- **كيف اكتشفتها؟** (كود/تجربة/قاعدة بيانات)
- **الحل المقترح** (خطوة عملية مختصرة)
- **مدى الصعوبة** (دقائق / ساعة / يوم)

في النهاية: **ملخص تنفيذي** بأهم ٥ مشاكل يجب إصلاحها فوراً.

## ٤. ما لن أفعله في هذه الجولة

- لن أعدّل أي كود أو قاعدة بيانات.
- لن أنفّذ عمليات تخريبية (حذف بيانات حقيقية، إلغاء اشتراكات).
- لن أختبر دفعات Paddle حقيقية — سأكتفي بفحص منطق الـ webhook.

## ٥. الوقت المتوقع

المراجعة شاملة وستستغرق عدة خطوات متتابعة (قراءة ~٣٠–٥٠ ملف + تجربة المتصفح + استعلامات DB). ستظهر النتائج في رسالة واحدة منظمة في نهاية الجولة.
